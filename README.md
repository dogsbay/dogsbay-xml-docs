# dogsbay-xml-docs

The documentation for **DogsBay XML**, served at
**https://dogsbay.ai/dogsbay-xml-docs/**.

Built with [DogsBay](https://github.com/dogsbay/dogsbay) and deployed to
Cloudflare Workers Static Assets via Workers Builds.

## Layout

```
content/            source markdown (dogsbay-md)
content/nav.yml     the sidebar
dogsbay.config.yml  site config
astro/              GENERATED — committed, built by Workers Builds
```

`astro/` is generated by `dogsbay site build` and committed. Workers Builds
runs the build in `astro/`; it does not run the DogsBay CLI. Edit `content/`,
rebuild, and commit both.

## Working on it

```bash
dogsbay site build     # content/ -> astro/
dogsbay site dev       # live preview at http://localhost:4321
dogsbay site check     # link and structure audit; run before committing
```

The preview serves under the site's base path, so the home page is at
`http://localhost:4321/dogsbay-xml-docs/` rather than at `/`.

## Deploying

Pushes to `main` trigger a Workers Build. It runs `npm run build` in `astro/`,
which is `astro build` plus the Pagefind search index and the base-path mount
step, and then `npx wrangler deploy`. Running only `astro build` produces a
site whose search 404s.

`astro/wrangler.jsonc` carries both routes: `dogsbay.ai/dogsbay-xml-docs` and
`dogsbay.ai/dogsbay-xml-docs/*`. The second does not match the first, and
without it the home page falls through to the apex worker.
